# 7.7.7 — аудит списка соревнований на главной (14.10.2026)
**Результат аудита.** Сервер отдаёт `/api/events` без какого-либо фильтра по дате и без пагинации (`SELECT … FROM events`, `ORDER BY date DESC`); сравнения с `datetime.now()` при выборке нет. Единственные места, где соревнование уходит из «Скоро»:
1. флаг `archived = 1` в самой базе (в списке не показывается, лежит в разделе «Архив» с кнопкой «Вернуть»; автоматически ставится только при импорте календаря сайта для дат, которые по часам сервера уже прошли);
2. в `ui.html` — группировка по дате на этом ПК: событие с датой «раньше сегодня» уходило в «Прошли — ещё не в архиве».
3. запуск с локальной базой, которой нет под ожидаемым именем: Windows прячет расширение, файл «reads» вместо `reads.db` → сервер создавал пустую базу, и соревнований не было совсем.

**Что сделано**
- `ui.html`: «Скоро» — все не архивные соревнования, которые не идут сейчас и не завершены, даже если дата уже прошла по часам ПК; «Завершены — ещё не в архиве» — только со статусом «завершено». Если в архиве есть соревнования, под списком подсказка с их числом.
- `hub.py`: `events_for_list()` — одна повреждённая строка выводится упрощённо, а не роняет весь список; даты вида `17.10.2026` приводятся к `2026-10-17`; пустые название, статус и архивный флаг заменяются безопасными значениями. Недостающие колонки в перенесённой базе по-прежнему добавляет миграция при открытии базы.
- `find_local_db`: при локальном запуске файл SQLite без расширения (`reads`, `reads.sqlite`) подхватывается вместо создания пустой базы; при старте в журнал пишется, какая база открыта и сколько в ней соревнований (в архиве — сколько).
- Автотесты: перенесённая база с датой `17.10.2026` и пустым статусом, файл без расширения, UI-группировка. Проверено в браузере с часами до и после 17 октября: «Открытое первенство СШОР по метаниям» остаётся в «Скоро».
