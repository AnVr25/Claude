# 5.1.0 — согласие отдельно, обезличивание заявок, внешние копии (152-ФЗ)

Оператор — только РСОО «ФЛАСО». Тренеры СШОР ЛВС работают в системе как тренеры и судьи, данные принадлежат Федерации.

## 1. Согласие отдельно от Политики (ч. 1 ст. 9 152-ФЗ, ред. с 01.09.2025)
- Во всех формах (заявка участника, эстафета, командная заявка, регистрация тренера) — отдельный блок
  «Согласие на обработку персональных данных»: полный текст на экране + своя отметка.
- Ознакомление с Политикой — **другая, самостоятельная** отметка. Без обеих сервер отвечает 400 (`consent`, `policy`).
- Текст согласия участника: оператор с ИНН и адресом, состав данных, цели (в т. ч. табло и диктор на месте
  соревнований, расчёт разрядов), действия, срок обезличивания, порядок отзыва. Тренера — свой текст
  (`GET /r/api/auth/trainer/consent`).
- У заявки и учётной записи тренера хранятся `consent_at`, `consent_hash` (отпечаток текста согласия) и
  `policy_hash` (отпечаток редакции Политики). Сами тексты всех редакций — в таблице `consent_texts`;
  администратор видит их в «Система → Пользователи → Редакции текстов согласий» (`GET /api/consents`).

## 2. Сроки и обезличивание
- Через `retention.applications_days` дней (по умолчанию 180; **согласуйте с юристом**) после окончания
  соревнования у заявок удаляются контакт и ФИО законного представителя, дата рождения сокращается до года
  (`YYYY-01-01`, отметка `anonymized_at`). Год нужен протоколам и разрядам. Выгрузки для Wiclax полную дату
  обезличенных заявок не отдают; в админке такая заявка помечена «заявка обезличена».
- Итоговые протоколы — бессрочный архив Оператора с обоснованием (подтверждение результатов и норм разрядов).
- Выполняется раз в час вместе с остальными сроками; вручную — `POST /api/system/retention` (администратор).
```json
"retention": {"applications_days": 180}
```

## 3. Внешние зашифрованные копии
`timing-offsite-backup` (cron.daily, ставит `install.sh`; первая копия — при установке):
1. снимок базы → gzip → AES-256 (`openssl enc -aes-256-cbc -pbkdf2 -iter 200000`), ключ `/etc/timing-hub/backup.key`
   (создаётся при первом запуске, права 600);
2. если есть `/etc/timing-hub/offsite.env` с `REMOTE` — rsync по SSH на другой сервер;
3. **проверка восстановления**: копия расшифровывается во временную папку, `PRAGMA integrity_check`, подсчёт
   соревнований/заявок/тренеров;
4. итог — `/var/lib/timing-hub/offsite/status.json`, видно в «Система → Внешние резервные копии»; там же кнопка
   «Скачать последнюю копию (зашифрована)» — для хранения на компьютере Федерации. Хранятся 14 последних копий.

```bash
# /etc/timing-hub/offsite.env — копия на второй сервер
REMOTE="backup@АДРЕС:/srv/sakhstart"
SSH_KEY="/root/.ssh/sakhstart_backup"
KEEP=14
```
Проверить вручную: `sudo timing-restore-check` (последняя копия) или
`sudo timing-restore-check ФАЙЛ --restore-to /tmp/reads.db` (расшифровать для восстановления).

**Ключ** `/etc/timing-hub/backup.key` сохраните отдельно от сервера (флешка в сейфе Федерации): без него копии
не открыть, а с ним и копией — открыть можно, поэтому ключ и копии храните раздельно.

## Что остаётся за Федерацией (не код)
- уведомление Роскомнадзора: проверить запись в реестре операторов (pd.rkn.gov.ru, ИНН 6501159635), цели и состав;
- приказ о назначении ответственного (Шаронов В. А.), положение об обработке ПДн, перечень допущенных лиц,
  акт оценки вреда, журнал обращений субъектов;
- согласия родителей при командных заявках: тренер подтверждает их наличие — Федерация вправе их запросить
  (бланк на каждого ребёнка или подтверждение родителем по ссылке — отдельная доработка);
- если понадобится открытая публикация результатов — отдельное согласие на распространение (ст. 10.1).
