# 5.0.0 — личный кабинет тренера и закрытые протоколы

## Для тренера
Страница **https://reg.fla65.ru/r/trainer** (ссылка «Вход для тренеров» — в подвале любой страницы `/r/`,
на странице соревнования и в списке событий).

1. **Регистрация** — ФИО, спортивная школа / клуб, электронная почта, пароль (от 8 символов), согласие на обработку ПДн.
2. **Подтверждение почты** — 6-значный код из письма. Действует 30 минут, 5 попыток, новый код — не чаще раза в минуту.
3. **Личный кабинет** — список соревнований, у которых организатор выложил стартовый или итоговый протокол,
   и кнопка «👁️ Посмотреть закрытый протокол». Дальше вход по почте и паролю.

Если тренер открыл ссылку на протокол без входа, после входа (или после ввода кода) он попадает прямо в этот протокол.

## Кто видит протоколы
| | гость | тренер с подтверждённой почтой | судья, администратор |
|---|---|---|---|
| `/r/<id>/protocol`, `results.json`, `startlist.json` | вход тренера (302 / 401) | да, выложенные, без чипов | да |
| `/protocol` в панели | вход тренера | переадресация в `/r/<id>/protocol` | да |
| `/api/events/<id>/startlist`, `/results` | 401 | 403 | да |
| админка, заявки, «Система», экраны судей | — | закрыто | по роли |

Календарь для fla65.ru (`/r/api/calendar`), страница события, форма регистрации и документы остаются открытыми.

## API
Те же адреса в панели (`/api/auth/trainer/…`) и в публичной части (`/r/api/auth/trainer/…`). POST — JSON с заголовком
`X-Requested-With: timing-hub`.
- `POST register` `{name, team, email, password, consent}` → `{ok, email, sent}`; повтор для неподтверждённой почты обновляет данные и шлёт новый код.
- `POST verify` `{email, code}` → подтверждение и сразу сеанс (cookie `ss_session`, HttpOnly, SameSite=Lax, Secure за HTTPS).
- `POST resend` `{email}`, `POST login` `{email, password, next}`, `POST logout`, `GET me`.
- `GET /r/api/trainer/events` — список для кабинета.

Администратор: `GET /api/trainers`, `POST /api/trainers/<id>/verify|block|unblock|delete` (раздел «Пользователи → Тренеры»).

## Хранение
Таблица `trainers`: id, name, team, email (уникальный, в нижнем регистре), password_hash (scrypt), is_verified,
verification_token (sha256 от кода — сам код не хранится), created_at, а также срок и попытки кода, блокировка,
последний вход, кто и как подтвердил. Сеанс тренера в общей таблице `sessions` с логином `trainer:<id>` — с логинами судей
не пересекается; блокировка, удаление и смена пароля сразу закрывают сеансы. Регистрация, подтверждение, вход и действия
администратора пишутся в журнал.

## Почта
Раздел `mail` в `/etc/timing-hub/config.json` (пример — `config/config.example.json`):
```json
"mail": {"host": "smtp.mail.ru", "port": 465, "security": "ssl", "user": "noreply@fla65.ru", "password": "…", "from": "SakhStart <noreply@fla65.ru>"}
```
Письмо уходит в отдельном потоке — приём отметок не ждёт почтовый сервер. Пока `mail` не заполнен, письма не уходят:
тренер видит, что его подтвердит организатор, а администратор нажимает «Подтвердить» в «Пользователи → Тренеры».
Для проверки без почты: `"mail": {"outbox_dir": "/var/lib/timing-hub/outbox"}` — письма складываются файлами `.eml`.

## 5.0.1 — Политика конфиденциальности и согласия (152-ФЗ)
- **`/privacy`** (и `/r/privacy`) — Политика обработки ПДн, файл `hub/privacy.html`, открыта без входа. Оператор — РОО «Федерация
  лёгкой атлетики Сахалинской области». Реквизиты (ИНН, ОГРН, адрес, почта, телефон) берутся из `config.json` → `"operator"`;
  незаполненные поля на странице не показываются. Текст описывает ровно то, что делает система: цели (протоколы, разряды по ЕВСК,
  АРМ судей, кабинет тренера), состав данных, отсутствие паспортов/СНИЛС/биометрии, хранение в РФ, TLS, VPN, хеши паролей,
  HttpOnly-сеансы, cookie, сроки, права субъекта (ст. 14, 20, 21 152-ФЗ). **Перед публикацией текст должен проверить юрист ФЛАСО.**
- Ссылка «Политика конфиденциальности» — в подвале страниц `/r/` (регистрация, кабинет тренера), на странице входа и в подвале админки.
- Тренер: обязательная галочка «Я даю согласие на обработку моих персональных данных и соглашаюсь с Политикой конфиденциальности»;
  без неё кнопка регистрации выключена, а сервер отвечает 400. В `trainers` записываются `consent_accepted`, `consent_at`
  и `consent_hash` — отпечаток редакции политики, с которой согласились.
- Заявка спортсмена: обязательная галочка «Я, как совершеннолетний участник или законный представитель…» со ссылкой на политику
  (как и раньше, у заявки сохраняются время согласия и отпечаток текста). Командная и эстафетная заявки — со ссылкой на политику.

## 5.0.2 — Политика по структуре eTiming, реквизиты РСОО «ФЛАСО», сроки хранения
- `/privacy` переписана по структуре политики eTiming (оператор, перечень данных с источниками, цели с правовыми основаниями,
  действия, сроки, третьи лица, трансграничная передача, меры защиты, права, отзыв согласия, изменения, история версий)
  без разделов о Яндекс.Метрике и Яндекс ID — аналитики и внешних сервисов в системе нет. Формулировки — под SakhStart.
- Оператор по умолчанию — РСОО «ФЛАСО» из карточки организации (ИНН, ОГРН, адрес, почта, городской телефон);
  ответственный за организацию обработки ПДн — Шаронов Виталий Александрович. Любое поле заменяется в `config.json` → `"operator"`.
  Банковские реквизиты, личный мобильный и руководители в политику не включены.
- Сроки из §5 соблюдаются автоматически (раз в час): неподтверждённые регистрации тренеров — 7 дней, тренер без входа 3 года —
  удаляется, истёкшие сеансы, журнал действий старше 3 лет; ежедневные копии базы — 30 дней (cron).
