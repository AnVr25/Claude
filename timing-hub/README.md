# Сервер хронометража (timing-hub)

Свой сервер, через который отметки с ридеров попадают в Wiclax: без облака производителя и с полным архивом у вас.

```
F800 + 4G-роутер ──VPN──┐
F800 + 4G-роутер ──VPN──┼──> СЕРВЕР: приём → база (архив) → выход для Wiclax ──VPN──> ноутбук с Wiclax
Другие системы (HTTP) ──┘                     └── страница состояния, выгрузка CSV
```

**Что делает сервер:**

- принимает отметки от ридеров через VPN: ридер может подключаться к серверу сам, а может ждать, пока сервер подключится к нему;
- хранит **все** сырые строки и все считывания в базе; повторная выгрузка памяти ридера после обрыва связи не создаёт дублей;
- отдаёт в Wiclax по стандартному протоколу «generic acquisition». Wiclax видит сервер как обычный ридер. Из 5–20 считываний одного прохождения в Wiclax уходит одно;
- выполняет перезапрос (REWIND) из Wiclax: если ноутбук терял связь, отметки за любой период можно забрать заново;
- показывает страницу состояния: кто на связи, сколько отметок, не врут ли часы ридера. Отметки выгружаются в CSV.

Проверено: 30 автоматических тестов на Python 3.10 и 3.12 (Ubuntu 22.04 и 24.04).

---

## Три вещи, которые нужно знать заранее

1. **Формат данных F800 пока неизвестен.** Сервер сохраняет всё, что пришло, и показывает сырые строки. Универсальный разбор (`"parser": "auto"`) понимает большинство текстовых форматов: номер чипа плюс дата и время в любом привычном виде. Если не поймёт, по первым реальным строкам настраивается шаблон (см. «Распознавание формата»). Если строки придут в виде `HEX:...`, формат двоичный, и без описания протокола от Feibot не обойтись.
2. **Финиш не вешаем только на 4G.** На финише ридер подключается к ноутбуку с Wiclax кабелем напрямую (через родную поддержку Feibot в Wiclax), а сервер работает вторым каналом и архивом. 4G используем для отсечек на трассе.
3. **На сервере нет ФИО.** В базе только номера чипов, время и коды точек. Имена участников остаются в Wiclax на ноутбуке. Это сильно упрощает юридическую часть (см. ниже).

## Шаг 1. Где арендовать сервер (законно)

### Какой сервер нужен

| Параметр | Значение |
|---|---|
| Тип | VPS (виртуальный сервер) на **KVM** или Hyper-V. Не OpenVZ/LXC: в них не работает VPN |
| ОС | Ubuntu 24.04 (или 22.04) |
| Мощность | 1 ядро, 1 ГБ памяти, 10–20 ГБ диска — с большим запасом |
| Сеть | Постоянный (статический) внешний IPv4 |
| Где | Дата-центр **в России**, провайдер — российское юрлицо |

### Какого провайдера взять

- **RUVDS** — есть дата-центр во **Владивостоке** (ближе всего к Сахалину), отдельная линейка серверов под 152-ФЗ, VPS от ~150 ₽/мес. https://ruvds.com
- **Timeweb Cloud** — KVM, дата-центры в Москве, Санкт-Петербурге и Новосибирске, есть серверы 152-ФЗ, оплата по счёту. https://timeweb.cloud
- Подойдёт и любой другой российский провайдер VPS на KVM.

Удалённость от Сахалина на точность не влияет: время отметки ставит сам ридер, а не сервер. Задержка сети влияет только на то, через сколько секунд отметка появится в Wiclax.

### Почему сервер должен быть в России

По ч. 5 ст. 18 152-ФЗ персональные данные граждан РФ при сборе записываются и хранятся в базах данных, находящихся в России. На сервере нет ФИО, но у организатора есть связка «чип ↔ участник». Поэтому номера чипов и время прохождения безопаснее считать персональными данными и держать их в России, не споря об этом с проверяющими. Зарубежные облака, включая облака производителей ридеров и самого Wiclax, для хранения не используем.

### Чей сервер: школа или федерация

| | Школа (ГАУ ДО СШОР) | Федерация (РСОО ФЛАСО) |
|---|---|---|
| Закупка | По Положению о закупке школы (223-ФЗ): малая закупка у единственного поставщика, договор, счёт, акты | Без 223-ФЗ: договор-оферта, оплата по счёту, быстро |
| Срок запуска | Недели (оформление закупки) | 1 день |
| Оборудование | Ридеры и сервер у одного владельца — проще отчитываться | Если ридеры школьные — оформить соглашение о сотрудничестве (передача данных хронометража федерации) |
| Оператор ПДн | Школа | Федерация |

**Моя рекомендация:** запустить и обкатать сервер на федерации, это быстро и дёшево. Если схема приживётся и станет постоянной для школьных стартов, перевести договор на школу при плановой закупке. Перенос — это копия одного файла базы и повторный запуск `install.sh`.

### Что нужно оператору персональных данных (в обоих вариантах)

- Уведомление Роскомнадзора об обработке ПДн (ст. 22 152-ФЗ). У школы оно, скорее всего, уже подано: проверьте, что среди целей есть проведение соревнований. Федерации, если она сама регистрирует участников, тоже нужно подать.
- Согласие участника на обработку ПДн в форме регистрации на старт.
- Опубликованная политика обработки ПДн.
- Если когда-нибудь на сервере появятся ФИО, в договоре с провайдером должно быть поручение на обработку ПДн (ч. 3 ст. 6 152-ФЗ). У провайдеров с линейкой «152-ФЗ» это обычно входит в договор.

> Юридические детали (закупка, уведомление, соглашение со школой) сверьте с юристом учреждения: здесь описан общий порядок, а не юридическое заключение.

## Шаг 2. Установка (около 15 минут)

1. У провайдера создайте VPS: **Ubuntu 24.04**, тариф с 1 ГБ памяти. Запишите **IP-адрес** и **пароль root**.
2. На компьютере с Windows 10/11 откройте **PowerShell**, перейдите в папку с архивом и скопируйте комплект на сервер (подставьте свой IP):
   ```
   cd $HOME\Downloads
   scp timing-hub.zip root@IP_СЕРВЕРА:/root/
   ```
3. Подключитесь к серверу:
   ```
   ssh root@IP_СЕРВЕРА
   ```
4. На сервере выполните:
   ```
   apt-get update && apt-get install -y unzip
   unzip timing-hub.zip && cd timing-hub
   sudo bash install.sh
   ```
5. В конце установщик напечатает адреса и **пароль страницы состояния**. Запишите их.
6. Проверьте, что всё работает:
   ```
   python3 /opt/timing-hub/tools/selftest.py --hub /opt/timing-hub/hub.py
   ```
   В конце должно быть: `Всё работает.`

Что сделал установщик: поставил VPN (WireGuard), включил firewall (снаружи открыты только SSH и порт VPN), поставил часовой пояс Asia/Sakhalin и синхронизацию времени, запустил сервер как системную службу (сам поднимается после перезагрузки), включил ежедневную копию базы и создал VPN-доступ для ноутбука с Wiclax.

## Шаг 3. VPN для ноутбука с Wiclax

1. Установите на ноутбук программу **WireGuard для Windows**: https://www.wireguard.com/install/
2. На сервере выполните:
   ```
   sudo timing-peer show wiclax-laptop
   ```
   и скопируйте текст между строками `=====`.
3. В WireGuard: **Добавить туннель → Добавить пустой туннель**, вставьте текст, сохраните, нажмите **Подключить**.
4. Откройте в браузере **http://10.66.0.1:8080**. Логин `admin`, пароль из шага 2. Должна открыться страница состояния.

Нужен ещё ноутбук или телефон: `sudo timing-peer add имя`. У каждого устройства должен быть свой доступ.

## Шаг 4. Подключение ридеров

### Ящики и ридеры из браузера (основной способ)

**Ящик** — роутер (Netcraze/Keenetic, MikroTik) с OpenVPN-клиентом и ридеры IPICO в его локальной сети. Сервер сам подключается к каждому ридеру по его родному адресу через VPN и переподключается при обрывах. Командная строка нужна один раз на ящик.

1. **Своя подсеть у каждого ящика:** ящик 1 — `10.19.1.x`, ящик 2 — `10.19.2.x` и так далее. Две одинаковые подсети одновременно работать не будут.
2. **Доступ для роутера ящика** (один раз):
   ```
   sudo timing-ovpn add-box box1 10.19.1.0/24
   ```
   Файл `/root/ovpn-clients/box1.ovpn` скачайте через WinSCP и импортируйте в роутер (OpenVPN-клиент). На вкладке «Оборудование» роутер появится как box1.
3. **У ридеров шлюз (gateway) — адрес роутера ящика** (например, `10.19.1.1`). Без этого ридер не сможет ответить серверу.
4. **В браузере:** «Оборудование» → «+ Добавить ридер» (или «Загрузить список» — по строке на ридер: `название; IP; порт; точка; ящик`) → «Подключить». Отключение, изменение и удаление — там же, кнопками.
5. **Точка** — код для Wiclax и протокола: несколько ридеров на одном финише ставьте в одну точку `FINISH`.
6. **Ридер — это железо, логика — в Wiclax.** За каждым ридером сервер навсегда закрепляет **личный порт для Wiclax** (9861, 9862…; виден в таблице ридеров). В Wiclax на каждый ридер — устройство «Общий»: адрес `10.66.0.1`, порт ридера. «Цель» (старт, отсечка, финиш) и «Бэкап линию» (дублирующий финиш) выставляете в Wiclax, как обычно; шаблон устройств сохраняется один раз. Один ридер на финише — достаточно одного устройства на общий порт `9854`. Колонка «Где стоит» — просто подпись для себя.
7. **«🔍 Найти ридеры»** — укажите сеть ящика (например `10.19.1`), сервер через VPN проверит адреса .1–.254 и покажет, где отвечает ридер; «Добавить» — и готово.

### Симулятор гонки (тренировка без железа)
«🧪 Симулятор» → «Сохранить и подключить»: появляется виртуальный ридер SIM со своим портом для Wiclax. «▶ Прогнать гонку» берёт участников с чипами из выбранного соревнования (или 30 выдуманных чипов) и за заданное число минут «прогоняет» их через финиш: по 4 считывания на проход, как у настоящего ридера. Отметки идут обычным путём — сервер → Wiclax. «🧹» стирает отметки симулятора (настоящие не трогаются). Перед реальной гонкой симулятор отключите или удалите.

### Файл соревнования для Wiclax (.clax)
Вкладка «Соревнования» → «⬇ Файл для Wiclax (.clax)»: готовый файл с дистанциями, временем стартов, участниками и чипами — открыть в Wiclax. Дистанции берутся из забегов (или «дистанция + категория»), старт — из времени забега или «Старт по часам». Собрать .clax без сервера: `python3 tools/make_clax.py событие.json` (формат описания — в начале файла).

### Обновление и откат
**Из браузера:** «Оборудование» → «Обновление сервера» → «⬆ Установить обновление» → выбрать timing-hub.zip. Архив проверяется, ставится root-службой `timing-update` (журнал там же), при сбое — автооткат. Работает начиная с версии 1.3.0 (первый раз её нужно поставить через WinSCP).

Перед каждым обновлением `install.sh` сам сохраняет прежнюю версию программы, настройки и копию базы в `/var/backups/timing-hub/` (5 последних). Если после обновления что-то не так:
```
sudo timing-rollback          # список копий
sudo timing-rollback last     # вернуть прежнюю программу и настройки (отметки не трогаются)
```
`--with-db` дополнительно возвращает базу — только если она испорчена: отметки после копии пропадут.

Временный вариант без роутера — ноутбук рядом с ридером (Windows, PowerShell от администратора):
```
netsh interface portproxy add v4tov4 listenaddress=<VPN-адрес ноутбука> listenport=10000 connectaddress=<IP ридера> connectport=10000
```
и в браузере ридер с адресом ноутбука в VPN.

**Часы IPICO** сбрасываются при выключении питания. Перед каждым стартом синхронизируйте их (Wiclax → устройство Ipico напрямую → часы), затем снова выключите прямое устройство в Wiclax.

### Вариант А (рекомендуемый): 4G-роутер с VPN рядом с ридером

Ридер F800 подключается кабелем или по Wi-Fi к 4G-роутеру с поддержкой WireGuard (MikroTik на RouterOS 7, Keenetic). SIM-карта стоит в роутере.

1. Создайте доступ для роутера:
   ```
   sudo timing-peer add finish-router --mikrotik
   ```
   - **MikroTik:** вставьте напечатанные команды в терминал роутера.
   - **Keenetic:** в веб-интерфейсе роутера «Другие подключения → WireGuard → Загрузить из файла» и загрузите файл настроек (его же показывает `sudo timing-peer show finish-router`).
2. Дальше зависит от того, как F800 отдаёт данные.
   - **Ридер сам отправляет на сервер** (источник `FINISH` в настройках по умолчанию). В сетевых настройках F800 укажите сервер `10.66.0.1`, порт `7001`, протокол TCP.
   - **Ридер ждёт подключения** (так к нему подключается Wiclax). В `config.json` включите источник `KM5`: `"enabled": true`, `"host"` — VPN-адрес роутера (`10.66.0.X` из `timing-peer list`), `"port"` — порт ридера. На роутере пробросьте этот порт на ридер: для MikroTik команда напечатана закомментированной.
3. Проверьте связь: `sudo timing-peer list`, в колонке «НА СВЯЗИ» должно стоять «да».

### Вариант Б: встроенный 4G F800 без VPN

Подходит, только если F800 умеет слать данные на произвольный IP:порт, но не умеет VPN.

1. В `config.json` у источника поставьте `"listen_host": "0.0.0.0"`.
2. Выполните `sudo bash install.sh --public-ingest`: установщик откроет в firewall порты таких источников.
3. В F800 укажите внешний IP сервера и порт (например `7001`).

Минус: порт открыт в интернет, и подделку туда может прислать кто угодно. Держите его открытым только на время старта: `sudo ufw delete allow 7001/tcp` закрывает, `sudo ufw allow 7001/tcp` открывает снова.

### Распознавание формата (первое подключение каждого ридера)

1. Подключите ридер и проведите чип над ковриком.
2. На странице состояния нажмите «строки» у этого ридера: там видно, что ридер прислал на самом деле.
3. Если растёт число **отметок**, формат понят, ничего делать не надо.
4. Если растёт **«не разобрано»**, проверьте строку командой:
   ```
   sudo python3 /opt/timing-hub/hub.py --config /etc/timing-hub/config.json --test-parse FINISH "сюда строку от ридера"
   ```
   и настройте шаблон (`"parser": "regex"`, пример ниже). Или пришлите 5–10 строк, и шаблон напишут за вас.
5. Строки вида `HEX:...` означают двоичный протокол. Нужно описание от Feibot.

## Шаг 5. Подключение Wiclax

1. Ноутбук должен быть подключён к VPN (шаг 3).
2. В Wiclax добавьте приём (acquisition) типа **«Generic»** (générique) с адресом **10.66.0.1**, порт **9854**.
   По желанию: положите файл `wiclax/TimingHub.chip-acquisition.xml` в папку `<папка Wiclax>\Ressources\Acquisitions\` (создайте её, если нет) и перезапустите Wiclax. Появится тип «Timing Hub» с готовым портом.
3. **Одна точка (финиш)** — одного устройства на 9854 достаточно. **Несколько точек** — на вкладке «Оборудование» в блоке Wiclax добавьте порт для каждой точки (9855 — KM5, 9856 — разворот…) и в Wiclax заведите по устройству «Общий» на каждый порт с нужной «Целью». Основной порт 9854 при этом не используйте, иначе отметки придут дважды.
4. Сопоставьте коды точек с точками хронометража в Wiclax. Код точки — поле `device` источника (`FINISH`, `KM5`…), в строке Wiclax это третье поле.
5. **Если связь ноутбука с сервером прерывалась**, сделайте в Wiclax перезапрос (rewind) за нужный период. Сервер отдаст всё из базы, без дублей.
6. **Часы.** Сервер не сдвигает время по команде «установить часы» из Wiclax: время отметки задаёт ридер. Поэтому перед стартом синхронизируйте часы ридеров и проверьте их тестовым чипом (колонка «Часы ридера» на странице состояния).

## Настройки: `/etc/timing-hub/config.json`

Изменить и применить:
```
sudo nano /etc/timing-hub/config.json
sudo python3 /opt/timing-hub/hub.py --config /etc/timing-hub/config.json --check
sudo systemctl restart timing-hub
```

### Источник (ридер)

| Поле | Что значит |
|---|---|
| `id` | Короткое имя латиницей: `FINISH`, `KM5` |
| `name` | Описание для страницы состояния |
| `enabled` | `true` / `false` |
| `mode` | `listen` — ридер сам подключается к серверу; `connect` — сервер подключается к ридеру; `http` — приём POST-запросами |
| `listen_host`, `listen_port` | Для `listen`: адрес и порт на сервере (`10.66.0.1`, `7001`, `7002`…) |
| `host`, `port` | Для `connect`: адрес ридера в VPN и его порт |
| `init_commands` | Для `connect`: команды, которые отправить ридеру после подключения, например `["START\r\n"]` |
| `parser` | `auto` — угадать формат; `regex` — по шаблону; `wiclax` — строки уже в формате Wiclax |
| `pattern` | Шаблон для `regex`: группы `chip` и время (`datetime`, `time`, `unix` или `unix_ms`), по желанию `antenna`, `rssi` |
| `datetime_format` | Формат даты-времени для группы `datetime`, по умолчанию `%Y-%m-%d %H:%M:%S.%f` |
| `device` | Код точки для Wiclax; по умолчанию равен `id` |
| `device_per_antenna` | `true` — к коду точки добавляется номер антенны (`FINISH1`, `FINISH2`) |
| `allow_receive_time` | `true` — если в строке нет времени, брать время приёма сервером. **Не включайте для финиша:** через 4G это неточно |
| `chip_strip_leading_zeros`, `chip_take_last` | Обрезать ведущие нули или оставить N последних символов номера чипа (под таблицу чипов в Wiclax) |
| `unix_tz_offset_hours` | Для времени в формате unix: сдвиг от UTC (Сахалин: `11`); по умолчанию — пояс сервера |

Пример шаблона для строки `E2801160600002084A5C1234,2026-10-06 10:15:30.123,1,-55`:
```json
"parser": "regex",
"pattern": "^(?P<chip>[0-9A-F]+),(?P<datetime>[0-9-]+ [0-9:.]+),(?P<antenna>\\d+),(?P<rssi>-?\\d+)",
"datetime_format": "%Y-%m-%d %H:%M:%S.%f"
```

### Общие

| Поле | Что значит |
|---|---|
| `wiclax.listen_port` | Порт для Wiclax (9854) |
| `wiclax.forward_filter_sec` | Считывания одного чипа на одной точке с интервалом меньше этого числа секунд считаются одним прохождением (3). `0` — отдавать в Wiclax всё |
| `wiclax.heartbeat_sec` | Как часто посылать Wiclax сигнал «на связи» (5 с) |
| `clock_warn_sec` | При каком расхождении часов ридера подсвечивать красным (2 с) |
| `web.password`, `web.api_key` | Пароль страницы и ключ для HTTP-приёма — сгенерированы при установке |

## Приём от других систем по HTTP

Например, программа на ноутбуке с IPICO может пересылать отметки на сервер, и тогда весь архив будет в одном месте:
```
curl -X POST "http://10.66.0.1:8080/api/reads?source=OTHER" \
     -H "X-Api-Key: КЛЮЧ_ИЗ_CONFIG" -H "Content-Type: application/json" \
     -d '[{"chip":"058001234567","time":"2026-10-06 10:15:30.123","antenna":1}]'
```
Поле `time` принимает строку (`2026-10-06 10:15:30.123`, `06-10-2026 10:15:30.123`, `10:15:30.123`) или число unix (в секундах или миллисекундах). Можно присылать и просто текстовые строки (`Content-Type: text/plain`): они разбираются по настройкам источника.

## Работа с соревнованиями в браузере

Меню сгруппировано по назначению: **Соревнование** (Соревнования · Регистрация · Проверка · Хронометраж · Результаты), **Документы** (Файлы · Архив), **Система** (Оборудование · Журнал); справа — **Экраны** для судьи, диктора, табло и протокола.

- **Файлы** — у каждого соревнования папки: «Положение и документы», «Заявки», «Для судей», «Протоколы», «Результаты», «Фото и прочее». Стартовый список сам кладётся в «Для судей» при «Сформировать забеги», снимок результатов — в «Результаты» при «Завершить». Файлы перетаскиваются в выбранную папку, переносятся между папками. Папка «Для судей» видна на телефоне судьи.
- **Оборудование** — сервер (время и его синхронизация, часовой пояс, брандмауэр, форма регистрации, сертификат), ресурсы (процессор, память, диск, размер базы и файлов, резервные копии), службы (сервер хронометража, OpenVPN, WireGuard, nginx), ридеры, подключения Wiclax, все VPN-профили (кто на связи, откуда, трафик) и кто открывал сервер за последний час (профиль, устройство, экран). Сведения о VPN и службах собирает root-скрипт `timing-sysinfo` каждые 10 секунд.

Адрес: **http://10.66.0.1:8080**, только при включённом VPN.

| Вкладка / экран | Что делает |
|---|---|
| **Соревнования** | Карточка старта: название, дата, место, точка финиша, время начала, организатор, главный судья и главный секретарь (идут в шапку и подписи протокола). **Забеги** — у каждого категория (Юноши, Девушки…) и дистанция, своя кнопка «Старт». Список участников `номер;чип;забег;ФИО;год;команда;категория` или таблица с заголовками в любом порядке: вставить или перетащить CSV/Excel. Чип можно не указывать — тогда участник отмечается только судьёй |
| **Проверка** | Перед стартом проносите чипы над ковриком: экран крупно показывает номер, ведёт список непроверенных и чипов «не из списка», подаёт звуковой сигнал |
| **Хронометраж** | СТАРТ общий или по забегам (время старта уходит в Wiclax), ФИНИШ забега (время забега останавливается), «+ Следующий забег», ручная отметка, лента отметок, предупреждения |
| **Результаты** | Место в забеге и общее место (все забеги одной категории и дистанции), ФИО, результат, отсечки, фильтр по забегу, поиск, CSV, кнопка «Протокол для печати». ✋ — ручная отметка |
| **Протокол** (`/protocol?event=N`) | Готовый к печати протокол A4: организатор, название, дата, место, начало; таблицы по категориям и дистанциям (итоговый) или по забегам; DNS/DNF; внизу «Главный судья» и «Главный секретарь» с ФИО. Кнопка «Печать / PDF» |
| **Журнал** | Кто, когда и что сделал: старт, сброс, ручные отметки, правка номеров |
| **Архив** | Завершённые соревнования по годам и месяцам, фильтр по году, поиск по названию и месту. У каждого — протоколы и файлы (загружаются перетаскиванием) и снимок результатов, который сохраняется сам при «Завершить» |
| **Судья** (`/judge`) | Мобильный экран для телефона: выбор забега, СТАРТ забега, ФИНИШ ЗАБЕГА (секундомер останавливается), «Создать следующий забег» с категорией и дистанцией, ввод номера (время фиксируется при первом нажатии цифры) или режим «Отсечки» (жать на каждого финишёра, номера вписать позже). Работает при пропадании связи: отметки копятся в телефоне и досылаются сами |
| **Диктор** (`/announcer`) | Крупно последний финишировавший со звуковым сигналом и список перед ним |
| **Табло** (`/board`) | Большие часы гонки и последние финишировавшие — для экрана на финише |

**Предупреждения** появляются сами: точка финиша не выбрана; нет связи с точкой или она молчит дольше заданного; чипы не из списка; отсечки судьи без номера; повторное прохождение финиша; подозрительно быстрый отрезок между точками (возможная срезка).

**Стадион, только судья** (без чипов): точка финиша — `JUDGE`, участники без чипа (`номер;;Забег 1;ФИО;год;команда`). Порядок на телефоне судьи:
1. Выбрать забег → **СТАРТ**. Секундомер пошёл.
2. По приходу — вводить номера (время фиксируется при первой цифре) или жать «Отсечки».
3. **ФИНИШ ЗАБЕГА** — время останавливается, поздние нажатия не учитываются.
4. **Создать следующий забег** — категория и дистанция подставятся от предыдущего → СТАРТ.
Если судья забыл нажать ФИНИШ, старт следующего забега сам завершит предыдущий (для соревнований с финишем `JUDGE` это включено по умолчанию, в карточке — галочка «Забеги идут по очереди»).

Ручное время округляется **вверх до 0,1 с** (правила лёгкой атлетики). Общее место считается среди всех забегов одной категории и дистанции; равный результат в разных забегах — одно место.

**Персональные данные.** ФИО, год рождения и команда хранятся на сервере (Россия) только для протокола. Нужны согласия участников на обработку (обычно в заявке) и уведомление Роскомнадзора об обработке ПДн, если его у организации ещё нет.

**Телефон судьи** подключается к VPN так же, как ноутбук: `bash /root/ovpn.sh add judge1`, файл `.ovpn` импортировать в приложение OpenVPN Connect на телефоне.

Для чиповых стартов официальным остаётся протокол Wiclax; для судейских стартов на стадионе протокол сервера (`/protocol`) можно печатать как итоговый.

## Регистрация участников (публичная форма)

Поток: **форма в интернете → заявки → секретарь подтверждает → «Сформировать забеги» → стартовый протокол → судья ведёт забеги → итоговый протокол.**

1. Вкладка **«Регистрация»**: отметить «Приём заявок открыт», срок, число дорожек, дистанции (по одной в строке), категории строками `Юноши;М;2010;2011` (название;пол;год с;год по — как в положении). «Сохранить» — появится ссылка и QR для афиши.
2. Участник (или тренер за группу) заполняет: фамилия, имя, отчество, дата рождения, пол, команда, тренер, дистанции и лучший результат, телефон/e-mail. Если на день старта нет 18 лет — обязательно ФИО родителя (законного представителя). Без галочки согласия на обработку ПДн заявка не уходит.
3. **Команда списком.** В форме есть вкладка «Команда списком (Excel)»: тренер скачивает шаблон (дистанции этих соревнований уже в выпадающем списке), заполняет, загружает — форма сразу показывает ошибки по строкам; тренер подтверждает наличие согласий участников/родителей и отправляет всех разом. Секретарь в админке может отдать тот же шаблон («⬇ Шаблон Excel») и загрузить присланный файл сам («Импорт из Excel», заявки сразу подтверждены). Принимается .xlsx и CSV.
4. Категория определяется сама по полу и году рождения. Кнопка «образец» ставит возрастные группы от года соревнований: мальчики/девочки до 12 и до 14 лет, юноши/девушки до 16 и до 18 лет, юниоры/юниорки до 20 лет, мужчины/женщины до 23 лет и взрослые — годы рождения можно поправить по положению. Повторная заявка того же человека на ту же дистанцию не принимается; похожие помечаются «повтор».
5. Секретарь: ✓ подтвердить / ✕ отклонить / поправить категорию, дистанцию, результат; «Подтвердить все»; «+ Внести заявку вручную».
6. **«Сформировать забеги»**: по дистанции и категории, посев по лучшему результату — сильнейшие в последнем забеге, внутри забега на центральных дорожках (8 дорожек: 4,5,3,6,2,7,1,8); без результата — в первых забегах. Номера присваиваются по порядку и при пересборке сохраняются.
7. Ручные правки: выпадающий список «Перенести» и номер дорожки. Поздние заявки после подтверждения — в блоке «Не распределены» → выбрать забег.
8. **«Стартовый протокол ↗»** — печать A4: забеги, дорожки, номера, ФИО, год, команда, тренер, заявленный результат, пустая графа «Результат».

После старта любого забега пересобрать забеги нельзя (защита от случайной кнопки) — только переносы в незастартовавших.

### Публикация формы в интернет: `timing-reg-setup`

Админка остаётся за VPN, наружу открываются только страницы `/r/...` по HTTPS.

1. В DNS домена (например fla65.ru) создайте A-запись `reg` → IP сервера. Подождите 5–30 минут.
2. На сервере: `sudo timing-reg-setup reg.fla65.ru ваша@почта.ru`

Скрипт ставит nginx, получает сертификат Let's Encrypt (открывает порт 80), включает в OpenVPN `port-share`: на порту 443 VPN-клиенты работают как раньше, а браузеры попадают на форму. VPN при этом перезапускается на несколько секунд. В конце проверяет, что форма отвечает, а `/api/...` снаружи — нет.

**Защита формы:** только HTTPS, приём только JSON до 16 КБ, лимиты частоты, ловушка для ботов, проверка полей на сервере, публичная часть не видит ни админку, ни API, ни файлы. Заявки всё равно проходят через секретаря.

**Персональные данные (152-ФЗ):** оператор — организатор из карточки соревнования. Текст согласия по умолчанию есть, но его нужно согласовать с юристом и опубликовать политику обработки ПДн на сайте организации; для несовершеннолетних согласие даёт родитель. Данные хранятся на сервере в России. После соревнований выгрузите заявки (CSV) в дело и удаляйте лишнее по сроку, указанному в политике.

### Обмен с Wiclax

- **Импорт из Wiclax (.clax)** — вкладка «Соревнования» → «Участники». Берутся номера, ФИО, год, пол, клуб, дистанции (Parcours → забеги с дистанцией и категорией) и **чипы**: связка номер ↔ чип восстанавливается из прохождений в файле. Удобно, чтобы на следующем старте с теми же номерами-чипами проверка чипов и результаты на сервере работали сразу.
- **Экспорт для Wiclax (CSV)** — стартовый список после регистрации и формирования забегов: номер, фамилия, имя, отчество, пол (M/F), год и дата рождения, клуб, дистанция в формате Wiclax («4000 м Женщины»), категория, тренер, чип. В Wiclax: импорт участников из файла, колонки сопоставить один раз.

## Частые проблемы

| Что видно | Что делать |
|---|---|
| Ридер «нет связи» | `sudo timing-peer list`: роутер на связи? Если нет — питание, SIM, баланс. Если да — проверить адрес и порт в настройках ридера |
| Растёт «не разобрано» | См. «Распознавание формата» |
| Красные «Часы ридера» | Синхронизировать время ридера (через интернет или вручную) и проверить тестовым чипом |
| Wiclax не подключается | Ноутбук в VPN? Открывается http://10.66.0.1:8080? Порт в Wiclax 9854? |
| В Wiclax нет части отметок после обрыва | Перезапрос (rewind) в Wiclax за этот период |
| Страница просит пароль, а он забыт | `sudo grep password /etc/timing-hub/config.json` |
| Сервер не стартует | `journalctl -u timing-hub -n 50`: в последних строках будет причина (чаще всего ошибка в config.json) |
