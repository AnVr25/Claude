# SakhStart (timing-hub) — судейско-секретарский АРМ стадиона и манежа

Свой сервер для соревнований по лёгкой атлетике: онлайн-заявки, нагрудные номера, посев, стартовые и итоговые протоколы, ручной ввод результатов судьями, табло, личный кабинет тренера. Данные хранятся у вас, без облака.

**С версии 7.0.0 система только для стадионов и манежей.** Чиповый хронометраж (транспондеры IPICO) и обмен с Wiclax вынесены в отдельный будущий проект и здесь не поддерживаются: ридеров, порта Wiclax и отметок транспондеров на сервере нет.

```
Тренеры и родители ── форма /r/ ──┐
Секретарь (браузер) ──────────────┼──> СЕРВЕР: заявки → номера → сетка → результаты → протоколы
Судьи на секторе (планшет) ───────┤                         └── табло, диктор, публикация на сайте
Табло на стадионе ────────────────┘
```

**Что делает сервер:**

- принимает заявки через публичную форму и кабинет тренера (согласия по 152-ФЗ, `/privacy`);
- мастер протоколов (этап «3. Протоколы»): 1) дисциплина и фильтр по полу и возрасту; 2) нагрудные номера, которые секретарь вписывает вручную — один номер на все виды спортсмена; 3) стартовый протокол (бег: забеги, 3 секундомера; техника: общий список, 6 попыток) и выгрузка в Excel; 4) ввод результатов (официальный результат считает сервер) и экстренная отмена старта; 5) итоговый протокол, корзина печати, публикация;
- табло с автопрокруткой, пульт табло, планшет судьи на секторе, экран диктора;
- разряды ЕВСК, командный зачёт, архив, журнал действий, резервные копии.

## Шаг 1. Где арендовать сервер (законно)

### Какой сервер нужен

| Параметр | Значение |
|---|---|
| Тип | VPS (виртуальный сервер) на **KVM** или Hyper-V. Не OpenVZ/LXC: в них не работает VPN |
| ОС | Ubuntu 24.04 (или 22.04) |
| Мощность | 1 ядро, 1 ГБ памяти, 10–20 ГБ диска — с большим запасом |
| Сеть | Постоянный (статический) внешний IPv4 |
| Где | Дата-центр **в России**, провайдер — российское юрлицо |

### Какого провайдера взять

- **RUVDS** — есть дата-центр во **Владивостоке** (ближе всего к Сахалину), отдельная линейка серверов под 152-ФЗ, VPS от ~150 ₽/мес. https://ruvds.com
- **Timeweb Cloud** — KVM, дата-центры в Москве, Санкт-Петербурге и Новосибирске, есть серверы 152-ФЗ, оплата по счёту. https://timeweb.cloud
- Подойдёт и любой другой российский провайдер VPS на KVM.

Удалённость от Сахалина на точность не влияет: результаты вводят судьи на месте, сервер только хранит и считает.

### Почему сервер должен быть в России

По ч. 5 ст. 18 152-ФЗ персональные данные граждан РФ при сборе записываются и хранятся в базах данных, находящихся в России. На сервере хранятся ФИО, даты рождения, контакты заявителей и результаты — это персональные данные, поэтому сервер должен быть в России, а оператор обязан выполнять требования 152-ФЗ (согласие, политика, сроки обезличивания — см. `/privacy` и `docs/pd-5.1.md`).

### Чей сервер: школа или федерация

| | Школа (ГАУ ДО СШОР) | Федерация (РСОО ФЛАСО) |
|---|---|---|
| Закупка | По Положению о закупке школы (223-ФЗ): малая закупка у единственного поставщика, договор, счёт, акты | Без 223-ФЗ: договор-оферта, оплата по счёту, быстро |
| Срок запуска | Недели (оформление закупки) | 1 день |
| Оборудование | Сервер и табло у одного владельца — проще отчитываться | Если оборудование школьное — оформить соглашение о сотрудничестве (передача данных хронометража федерации) |
| Оператор ПДн | Школа | Федерация |

**Моя рекомендация:** запустить и обкатать сервер на федерации, это быстро и дёшево. Если схема приживётся и станет постоянной для школьных стартов, перевести договор на школу при плановой закупке. Перенос — это копия одного файла базы и повторный запуск `install.sh`.

### Что нужно оператору персональных данных (в обоих вариантах)

- Уведомление Роскомнадзора об обработке ПДн (ст. 22 152-ФЗ). У школы оно, скорее всего, уже подано: проверьте, что среди целей есть проведение соревнований. Федерации, если она сама регистрирует участников, тоже нужно подать.
- Согласие участника на обработку ПДн в форме регистрации на старт.
- Опубликованная политика обработки ПДн.
- Если когда-нибудь на сервере появятся ФИО, в договоре с провайдером должно быть поручение на обработку ПДн (ч. 3 ст. 6 152-ФЗ). У провайдеров с линейкой «152-ФЗ» это обычно входит в договор.

> Юридические детали (закупка, уведомление, соглашение со школой) сверьте с юристом учреждения: здесь описан общий порядок, а не юридическое заключение.

## Шаг 2. Установка (около 15 минут)

1. У провайдера создайте VPS: **Ubuntu 24.04**, тариф с 1 ГБ памяти. Запишите **IP-адрес** и **пароль root**.
2. На компьютере с Windows 10/11 откройте **PowerShell**, перейдите в папку с архивом и скопируйте комплект на сервер (подставьте свой IP):
   ```
   cd $HOME\Downloads
   scp timing-hub.zip root@IP_СЕРВЕРА:/root/
   ```
3. Подключитесь к серверу:
   ```
   ssh root@IP_СЕРВЕРА
   ```
4. На сервере выполните:
   ```
   apt-get update && apt-get install -y unzip
   unzip timing-hub.zip && cd timing-hub
   sudo bash install.sh
   ```
5. В конце установщик напечатает адреса и **пароль страницы состояния**. Запишите их.
6. Проверьте, что всё работает:
   ```
   python3 /opt/timing-hub/tools/selftest.py --hub /opt/timing-hub/hub.py
   ```
   В конце должно быть: `Всё работает.`

Что сделал установщик: поставил VPN (WireGuard), включил firewall (снаружи открыты только SSH и порт VPN), поставил часовой пояс Asia/Sakhalin и синхронизацию времени, запустил сервер как системную службу (сам поднимается после перезагрузки), включил ежедневную копию базы и создал VPN-доступ для ноутбука секретаря.

## Шаг 3. VPN для ноутбука секретаря

1. Установите на ноутбук программу **WireGuard для Windows**: https://www.wireguard.com/install/
2. На сервере выполните:
   ```
   sudo timing-peer show secretary-laptop
   ```
   и скопируйте текст между строками `=====`.
3. В WireGuard: **Добавить туннель → Добавить пустой туннель**, вставьте текст, сохраните, нажмите **Подключить**.
4. Откройте в браузере **http://10.66.0.1:8080**. Логин `admin`, пароль из шага 2. Должна открыться страница состояния.

Нужен ещё ноутбук или телефон: `sudo timing-peer add имя`. У каждого устройства должен быть свой доступ.

## Обновление и откат
**Из браузера:** «Оборудование» → «Обновление сервера» → «⬆ Установить обновление» → выбрать timing-hub.zip. Архив проверяется, ставится root-службой `timing-update` (журнал там же), при сбое — автооткат. Работает начиная с версии 1.3.0 (первый раз её нужно поставить через WinSCP).

Перед каждым обновлением `install.sh` сам сохраняет прежнюю версию программы, настройки и копию базы в `/var/backups/timing-hub/` (5 последних). Если после обновления что-то не так:
```
sudo timing-rollback          # список копий
sudo timing-rollback last     # вернуть прежнюю программу и настройки (отметки не трогаются)
```
`--with-db` дополнительно возвращает базу — только если она испорчена: отметки после копии пропадут.

## Настройки: `/etc/timing-hub/config.json`

Изменить и применить:
```
sudo nano /etc/timing-hub/config.json
sudo python3 /opt/timing-hub/hub.py --config /etc/timing-hub/config.json --check
sudo systemctl restart timing-hub
```

| Поле | Что значит |
|---|---|
| `db_path` | Файл базы SQLite (по умолчанию `/var/lib/timing-hub/reads.db`) |
| `web.listen_host`, `web.listen_port` | Адрес и порт админки (внутри VPN) |
| `web.password`, `web.api_key` | Пароль страницы и ключ API — сгенерированы при установке |
| `public` | Публичная форма регистрации (локальный порт, наружу — через nginx) |
| `operator`, `retention`, `mail` | Реквизиты оператора ПДн, сроки обезличивания, почта для кодов тренеров |

Ключи `sources`, `wiclax`, `store_raw`, `raw_memory_lines`, `clock_warn_sec` из старых настроек сервер игнорирует. При первом запуске версии 7.0.0 база обновляется сама: таблицы чиповых отметок (`reads`, `raw`, `readers`, `wiclax_ports`) удаляются, строки участников получают собственный номер `id` (один нагрудный номер может стоять у спортсмена в нескольких дисциплинах). **Перед обновлением сохраните копию базы.**

## Работа с соревнованиями в браузере

Верхняя панель этапов постоянная: **1 Подготовка → 2 Регистрация → 3 Протоколы → 4 Выдача номеров → 5 Ввод результатов → 6 Результаты → 7 Документы**.

| Этап | Что делают |
|---|---|
| **1. Подготовка** | Карточка соревнования: название, дата, место, организатор, главный судья и секретарь, дисциплины, уровень (от него зависят разряды), сайт |
| **2. Регистрация** | Только онлайн-заявки: анкеты из формы, «Подтвердить / Отклонить», правка разряда и категории, ручная заявка, импорт командной заявки (Excel), приём заявок |
| **3. Протоколы** | Мастер из 5 шагов: 1 дисциплина и фильтр; 2 нагрудные номера (вписываются вручную, кнопка «💾 Сохранить нагрудные номера»; один номер на все виды спортсмена); 3 стартовый протокол, Excel, «❌ Сбросить сетку»; 4 ввод результатов, «🛑 Отменить старт / Сбросить время»; 5 итоговый протокол, корзина печати, публикация |
| **4. Выдача номеров** | Отметки о выдаче стартовых пакетов (по человеку) |
| **5. Ввод результатов** | Открывает шаг 4 Мастера |
| **6. Результаты** | Протокол по ходу соревнований, места, разряды |
| **7. Документы** | Файлы для судей и публикации, протоколы |

**Результаты.** Судья вводит 1, 2 или 3 секундомера (бег) или до 6 попыток (техника). Официальный результат считает только сервер: три секундомера — средний, два — худший, один — само значение, округление вверх до 0,1 с. На табло и в итоговом протоколе — один результат.

**Нагрудные номера** секретарь вписывает сам; автоматической нумерации нет. Спортсмен определяется по фамилии, имени и году рождения: если он заявлен на несколько дисциплин, введённый номер записывается во все его дисциплины. Номер можно менять в любой момент, результаты переедут вместе с ним.

**Очистка номеров.** На шаге 2 красная кнопка «❌ Очистить все номера дисциплины» стирает номера у всех участников дисциплины (и у тех же людей в других видах); если уже введены результаты, сначала очистите протокол.

**Публичный список для тренеров.** Переключатель на этапе «2. Регистрация» открывает на странице формы список «прошли регистрацию»: только «Фамилия И.», возрастная группа и дисциплины. Протоколы остаются закрытыми — в личном кабинете тренера.

**Сброс сетки** принудительно обнуляет время старта выбранной дисциплины и удаляет забеги; после этого список формируется заново и в него входят все подтверждённые участники.

## Вход через браузер без VPN (с версии 2.1)

Панель открывается из любого браузера: **https://reg.fla65.ru/login** (адрес — ваш домен формы регистрации).
VPN нужен только для администрирования сервера.

- Первый вход — тем же логином и паролем, что и раньше (`web.user` / `web.password` из настроек).
  Сразу смените пароль: меню с логином вверху справа → «Сменить пароль».
- Пользователи заводятся в «Система → Пользователи». Роли:
  **администратор** — всё; **секретарь** — всё, кроме «Системы»; **судья** — телефон судьи, табло, диктор, протокол.
- Вход живёт 30 дней на устройстве; «Выйти» в том же меню. После 10 неверных паролей подряд вход с адреса закрывается на 10 минут.
- Включается само при обновлении: `install.sh` направляет на панель всё, кроме `/r/…`, на домене регистрации
  (nginx, файл `/etc/nginx/sites-available/timing-reg-https`, прежняя копия — `.bak`).

## Сайт fla65.ru: календарь, страницы событий, протоколы (с версии 2.1)

SakhStart — единая база событий федерации. Сайт показывает её сам:

1. Событие заводится в панели. В «Подготовке» блок **«На сайте fla65.ru»**: «Показывать в календаре», «Проводим мы»,
   уровень, коротко о событии, трансляция, фото, ссылки.
2. У нашего события появляется страница `https://reg.fla65.ru/r/<код>`: регистрация, стартовый протокол, результаты
   (во время старта — онлайн), документы, фото, трансляция.
3. Документы (положение, схема трассы…) — на этапе «Документы», галочка **«на сайте»**. Там же переключатели
   «Стартовый протокол на сайте» и «Результаты на сайте».
4. На fla65.ru календарь — один HTML-блок с виджетом (`fla65/calendar-block.html`, инструкция в `fla65/README.md`).
   Данные: `GET /r/api/calendar?year=2026` (формат — `docs/public-api.md`).
5. Календарь 2026 с сайта перенесён в файл `hub/seed/calendar-2026.json`: на главной панели кнопка
   «Загрузить календарь ФЛАСО 2026» (прошедшие сразу уходят в архив).

### Формат соревнования
Только стадион и манеж: забеги по дорожкам и технические виды (общий список, попытки). Хронометраж: **ручной секундомер** (секретарь или судья вписывает результаты: 12.84, 1:05.32; DNS/DNF/DQ), «судья на финише» с отсечками или FinishLynx (в следующей версии результаты пойдут в тот же ввод).

## Регистрация участников (публичная форма)

Поток: **форма в интернете → заявки → секретарь подтверждает → «Сформировать забеги» → стартовый протокол → судья ведёт забеги → итоговый протокол.**

1. Вкладка **«Регистрация»**: отметить «Приём заявок открыт», срок, число дорожек, дистанции (по одной в строке), категории строками `Юноши;М;2010;2011` (название;пол;год с;год по — как в положении). «Сохранить» — появится ссылка и QR для афиши.
2. Участник (или тренер за группу) заполняет: фамилия, имя, отчество, дата рождения, пол, команда, тренер, дистанции и лучший результат, телефон/e-mail. Если на день старта нет 18 лет — обязательно ФИО родителя (законного представителя). Без галочки согласия на обработку ПДн заявка не уходит.
3. **Команда списком.** В форме есть вкладка «Команда списком (Excel)»: тренер скачивает шаблон (дистанции этих соревнований уже в выпадающем списке), заполняет, загружает — форма сразу показывает ошибки по строкам; тренер подтверждает наличие согласий участников/родителей и отправляет всех разом. Секретарь в админке может отдать тот же шаблон («⬇ Шаблон Excel») и загрузить присланный файл сам («Импорт из Excel», заявки сразу подтверждены). Принимается .xlsx и CSV.
4. Категория определяется сама по полу и году рождения. Кнопка «образец» ставит возрастные группы от года соревнований: мальчики/девочки до 12 и до 14 лет, юноши/девушки до 16 и до 18 лет, юниоры/юниорки до 20 лет, мужчины/женщины до 23 лет и взрослые — годы рождения можно поправить по положению. Повторная заявка того же человека на ту же дистанцию не принимается; похожие помечаются «повтор».
5. Секретарь: ✓ подтвердить / ✕ отклонить / поправить категорию, дистанцию, результат; «Подтвердить все»; «+ Внести заявку вручную».
6. **«Сформировать забеги»**: по дистанции и категории, посев по лучшему результату — сильнейшие в последнем забеге, внутри забега на центральных дорожках (8 дорожек: 4,5,3,6,2,7,1,8); без результата — в первых забегах. Номера присваиваются по порядку и при пересборке сохраняются.
7. Ручные правки: выпадающий список «Перенести» и номер дорожки. Поздние заявки после подтверждения — в блоке «Не распределены» → выбрать забег.
8. **«Стартовый протокол ↗»** — печать A4: забеги, дорожки, номера, ФИО, год, команда, тренер, заявленный результат, пустая графа «Результат».

После старта любого забега пересобрать забеги нельзя (защита от случайной кнопки) — только переносы в незастартовавших.

### Публикация формы в интернет: `timing-reg-setup`

Админка остаётся за VPN, наружу открываются только страницы `/r/...` по HTTPS.

1. В DNS домена (например fla65.ru) создайте A-запись `reg` → IP сервера. Подождите 5–30 минут.
2. На сервере: `sudo timing-reg-setup reg.fla65.ru ваша@почта.ru`

Скрипт ставит nginx, получает сертификат Let's Encrypt (открывает порт 80), включает в OpenVPN `port-share`: на порту 443 VPN-клиенты работают как раньше, а браузеры попадают на форму. VPN при этом перезапускается на несколько секунд. В конце проверяет, что форма отвечает, а `/api/...` снаружи — нет.

**Защита формы:** только HTTPS, приём только JSON до 16 КБ, лимиты частоты, ловушка для ботов, проверка полей на сервере, публичная часть не видит ни админку, ни API, ни файлы. Заявки всё равно проходят через секретаря.

**Персональные данные (152-ФЗ):** оператор — организатор из карточки соревнования. Текст согласия по умолчанию есть, но его нужно согласовать с юристом и опубликовать политику обработки ПДн на сайте организации; для несовершеннолетних согласие даёт родитель. Данные хранятся на сервере в России. После соревнований выгрузите заявки (CSV) в дело и удаляйте лишнее по сроку, указанному в политике.

## Обслуживание

| Задача | Команда |
|---|---|
| Журнал сервера в реальном времени | `journalctl -u timing-hub -f` |
| Перезапустить сервер | `sudo systemctl restart timing-hub` |
| Состояние службы | `systemctl status timing-hub` |
| Список VPN-доступов | `sudo timing-peer list` |
| Удалить доступ (потерян роутер или ноутбук) | `sudo timing-peer remove имя` |
| Обновить программу сервера | распаковать новый комплект и снова `sudo bash install.sh`: настройки, ключи и база сохранятся |
| Обновления безопасности ОС | `sudo apt-get update && sudo apt-get upgrade -y` (раз в месяц, не в день старта) |
| Резервные копии | автоматически каждый день в `/var/lib/timing-hub/backups/`, хранятся 30 дней |

## Частые проблемы

| Что видно | Что делать |
|---|---|
| Страница просит пароль, а он забыт | `sudo grep password /etc/timing-hub/config.json` |
| Сервер не стартует | `journalctl -u timing-hub -n 50`: в последних строках будет причина (чаще всего ошибка в config.json) |
| «Сбросить сетку» раньше не работала после ошибочного старта | С 7.0.0 сброс всегда обнуляет время старта и снимает блокировку |
| Номер спортсмена разный в разных дисциплинах | Шаг 2 Мастера: сохраните номер — он запишется во все виды спортсмена |
