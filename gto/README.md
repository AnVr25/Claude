# ГТО: учёт результатов (ступени V–IX)

Веб-приложение для Федерации лёгкой атлетики Сахалинской области. В нём хранятся результаты сдачи нормативов ГТО по студентам с привязкой к институту и группе. По официальным нормативам с gto.ru приложение само считает знак отличия.

## Роли

| Роль | Что может |
|---|---|
| **Администратор** | всё, что «Ввод результатов», плюс заводит пользователей, выдаёт пароли, блокирует |
| **Ввод результатов** | добавляет и импортирует студентов, вносит, меняет и удаляет результаты |
| **Просмотр** (учителя физкультуры) | ищет студентов, смотрит результаты и даты, выгружает CSV |

Каждый входит по своему логину и паролю. Права проверяет сервер, а не только интерфейс.

## Что умеет

- Таблица: ФИО, институт, группа, ступень, знак, затем результаты по каждому испытанию. Цвет ячейки показывает уровень: золото, серебро, бронза или «не выполнено».
- Мгновенный поиск по ФИО и фильтры по институту, группе, ступени, полу и полученному знаку.
- Карточка студента со всеми испытаниями ступени. Для каждого результата видны дата испытания и кто и когда его внёс, а также каких обязательных испытаний не хватает до знака.
- Ввод результата в формате «12:20» или «8,4» с подсказкой, на какой знак он тянет.
- Импорт списка студентов прямо из Excel (копировать и вставить) или из CSV. Экспорт всей таблицы в CSV для Excel.
- Журнал всех изменений (таблица `audit` в базе).

### Как считается знак

Нормативы взяты с gto.ru для ступеней V–IX, отдельно для юношей и девушек (`public/norms.js`).

Знак уровня N дают, если выполнены все четыре обязательные категории (скорость, выносливость, гибкость, сила) не ниже N и всего категорий на уровне N набирается 5 для бронзы и серебра или 6 для золота. Из каждой категории засчитывается лучшее испытание.

## Установка на сервер

Нужен **Node.js 22.5 или новее**. Сторонних npm-пакетов нет, база данных — встроенный SQLite.

```bash
git clone https://github.com/AnVr25/Claude.git && cd Claude/gto
node --no-warnings cli.js add-user admin admin "Ваше имя"   # выведет пароль администратора
PORT=3000 npm start
```

Остальных пользователей удобнее заводить в самом приложении (кнопка «Пользователи»). Из консоли тоже можно:

```bash
node --no-warnings cli.js add-user ivanova viewer "Иванова М. П."
node --no-warnings cli.js reset-password ivanova
node --no-warnings cli.js list-users
```

### Переменные окружения

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `PORT` | `3000` | порт |
| `HOST` | `127.0.0.1` | адрес; оставьте так, если впереди стоит nginx |
| `GTO_DB` | `./data/gto.sqlite` | файл базы данных |
| `GTO_SECURE_COOKIE` | — | `1`, когда сайт работает по HTTPS (обязательно в боевом режиме) |

### Поддомен gto.fla65.ru через nginx

```nginx
server {
    server_name gto.fla65.ru;
    listen 443 ssl;  # сертификат — например, certbot --nginx
    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
    }
}
```

Автозапуск через systemd (`/etc/systemd/system/gto.service`):

```ini
[Unit]
Description=GTO results
After=network.target

[Service]
WorkingDirectory=/opt/gto
ExecStart=/usr/bin/node --no-warnings server.js
Environment=PORT=3000 GTO_SECURE_COOKIE=1
Restart=always
User=gto

[Install]
WantedBy=multi-user.target
```

### Резервные копии

Все данные лежат в одном файле `data/gto.sqlite`. Копировать его можно на лету:

```bash
sqlite3 data/gto.sqlite ".backup '/backup/gto-$(date +%F).sqlite'"
```

## Персональные данные

В базе хранятся ФИО студентов, то есть персональные данные по 152-ФЗ. Сервер должен находиться в России, а у учебных заведений должно быть основание передавать эти данные (согласие или договор).
